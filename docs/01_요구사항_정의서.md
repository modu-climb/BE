# 요구사항 정의서

> 📌 고정 카메라로 찍은 볼더링 영상 한 편을 받아 사람·홀드·벽의 상대적 공간 관계를 추정하고, 체형에 맞는 다음 동작 후보를 제시한다.
>
> 8주 MVP 목표는 "업로드 → 내 문제 홀드 확정 → 자세·공간 분석 → 피드백 → 재시도 비교" 한 바퀴를 이용자 50명이 돌려보는 것이다.

## 핵심 사용자 흐름

1. 스마트폰을 한 곳에 고정하고 전신과 벽이 보이게 촬영한다.
2. 영상을 업로드하고 키·윙스팬을 한 번 입력한다.
3. 서비스가 홀드를 탐지하면, 자기 문제의 홀드 하나(보통 시작 홀드)를 탭한다.
4. 확신도가 낮은 홀드만 추가·제외 확인을 받는다.
5. 실패 구간, 자세·공간 지표, 다음 동작 후보를 장면과 함께 본다.
6. 같은 문제의 재시도 영상을 올려 이전 시도와 비교한다.

## 기능 요구사항

| ID | 구분 | 요구사항명 | 설명 | 우선순위 | MVP |
| --- | --- | --- | --- | --- | --- |
| FR-01 | 회원 | 신체 프로필 등록 | 키·윙스팬을 등록·수정한다. 과거 분석은 당시 값을 스냅샷으로 유지한다. | 상 | O |
| FR-02 | 영상 | 영상 업로드 | presigned URL로 스토리지에 직접 업로드한다. 1편당 최대 60초, 1인 볼더링. | 상 | O |
| FR-03 | 영상 | 입력 영상 검증 | 카메라 흔들림·길이·해상도를 검사하고, 부적합하면 사유와 재촬영 가이드를 보여준다. | 상 | O |
| FR-04 | 홀드 | 홀드 자동 탐지 | 사람 없는 벽 기준 이미지를 만들고 모든 홀드에 ID와 마스크를 부여한다. | 상 | O |
| FR-05 | 홀드 | 기준 홀드 선택 | 사용자가 자기 문제의 홀드 하나를 탭해 기준 샘플로 지정한다. | 상 | O |
| FR-06 | 홀드 | 문제 소속 추정·확인 | 색 분포·다중 프레임 관측으로 소속을 추정하고, 확신도가 낮은 홀드만 확인받는다. 근거가 부족하면 "보류"로 둔다. | 상 | O |
| FR-07 | 홀드 | 누락 홀드 수동 추가 | 탐지되지 않은 홀드를 탭하면 SAM 2로 영역을 분리해 추가한다. | 중 | O |
| FR-08 | 분석 | 자세 추적·오버레이 | 전 프레임 관절 좌표를 추적하고 영상 위에 스켈레톤·접촉 홀드를 겹쳐 재생한다. | 상 | O |
| FR-09 | 분석 | 공간 지표 산출 | 정렬된 깊이로 골반-벽 상대 거리, 홀드 돌출, 벽 경사를 추정한다. 수치는 "추정"으로 표기한다. | 상 | O |
| FR-10 | 분석 | 실패 지점 탐지 | 접촉 이벤트 열에서 마지막 성공 접촉과 이탈 시점을 찾는다. | 상 | O |
| FR-11 | 피드백 | 다음 동작 추천 | 윙스팬·현재 자세·문제 홀드 배치로 다음 손발 위치 후보 2\~3개를 제시하고, 문장마다 근거 지표를 연결한다. | 상 | O |
| FR-12 | 분석 | 진행 상황 표시 | 분석 단계와 진행률을 실시간(SSE)으로 보여주고, 사용자 입력이 필요하면 알린다. | 중 | O |
| FR-13 | 비교 | 시도 비교 | 같은 문제·같은 촬영 위치의 두 시도를 지표와 무브 순서로 나란히 비교한다. | 상 | O |
| FR-14 | 피드백 | 코치 검토 | 코치가 자동 분석에 동의·수정 의견을 남긴다. 자동 결과를 덮어쓰지 않고 별도 기록한다. | 중 | O |
| FR-15 | 기록 | 분석 이력 | 문제별·날짜별로 과거 시도와 리포트를 조회한다. | 중 | O |
| FR-16 | 결제 | 무료 체험·분석권 | 무료 분석 횟수 한도를 두고 건별 분석권 결제를 시험 운영한다. | 하 | 7\~8주차 |
| FR-17 | 확장 | 3D 아바타 시뮬레이션 | 신체 비율을 반영한 아바타로 대안 동작을 설명한다. | - | X |
| FR-18 | 확장 | 암장·코치 회원 관리, 루트 통계 | 회원별 영상 관리와 루트별 정체 구간 통계를 제공한다. | - | X |

## 비기능 요구사항

| ID | 구분 | 요구사항 | 기준 |
| --- | --- | --- | --- |
| NFR-01 | 성능 | 결과 제공 시간 | 업로드 완료부터 리포트까지 중앙값 측정. 목표치는 인터뷰(등반 직후 vs 운동 후)로 확정 |
| NFR-02 | 비용 | 영상당 GPU 비용 상한 | 영상당 GPU 초를 기록하고, 키프레임 수·해상도를 상한에 맞춰 조정 |
| NFR-03 | 신뢰성 | 작업 재시도·멱등성 | 실패 작업 최대 2회 재시도, 워커 이벤트는 jobId+phase+attemptNo로 중복 제거 |
| NFR-04 | 유지보수 | 모델 교체 가능성 | 도메인은 모델 이름을 모른다. 깊이·포즈·세그멘테이션은 워커 내부 포트 뒤에 둔다 |
| NFR-05 | 추적성 | 파이프라인 버전 기록 | 모든 결과에 pipelineVersion과 모델 식별자를 저장 |
| NFR-06 | 설명가능성 | 근거 있는 피드백 | 피드백 문장마다 근거 지표 ID 1개 이상, 추정 수치는 범위로 표기 |
| NFR-07 | 보안 | 자원 접근 제어 | 본인 영상·리포트만 접근, presigned URL 짧은 만료, 워커 스트림은 내부망 전용 |
| NFR-08 | 개인정보 | 동의·보관·삭제 | 분석 동의와 학습 활용 동의를 분리, 원본 보관 기한 설정, 삭제 요청 시 산출물까지 삭제 |
| NFR-09 | 관측성 | 단계별 메트릭 | 파이프라인 단계별 처리 시간·실패 사유·반려 사유를 집계 |
