# ADR-0005 ID는 UUIDv7

- 상태: 제안
- 날짜: 2026-10-13

## 배경

ERD는 모든 PK를 `uuid`로 정했다. 무작위 UUIDv4는 B-tree 인덱스에 흩어져 쓰기 성능과 캐시 효율이 떨어진다. 또한 워커 메시지, 스토리지 키, 로그에 ID가 그대로 노출된다.

## 결정

- 모든 애그리거트 ID는 **UUIDv7**(시간 순 정렬)을 쓴다.
- ID는 DB가 아니라 **도메인에서 생성**한다. 애그리거트를 만들 때 ID가 정해져야 저장 전에 이벤트·스토리지 키에 쓸 수 있다.
- 코드에서는 `ClimberId`, `AttemptId`처럼 값 타입으로 감싸 다른 ID와 섞이지 않게 한다.
- PostgreSQL 컬럼 타입은 `uuid`다.

## 결과

- 좋아지는 점
  - 시간 순으로 쌓여 인덱스 지역성이 좋고, 생성 순서로 정렬할 수 있다.
  - 순번 ID와 달리 다른 회원의 자원 개수·ID를 추측하기 어렵다.
- 감수할 점
  - ID에서 생성 시각을 대략 알 수 있다. 민감하지 않은 정보로 본다.
  - UUIDv7 생성 라이브러리가 필요하다(M1에서 선정).
