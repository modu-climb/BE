# ADR-0001 BE(Spring Boot)와 AI(Python 워커) 분리

- 상태: 승인
- 날짜: 2026-10-13

## 배경

백엔드를 Java + DDD로 만들려고 한다. 분석은 GPU에서 영상 한 편당 수 초\~수 분이 걸리는 배치 작업이고, GPU 1장당 워커 1개가 작업 1개씩 처리한다. FastAPI 하나로 API와 AI를 모두 만드는 안도 검토했다.

## 결정

- API·도메인·DB는 **Spring Boot**가 소유한다.
- 분석은 **Python 워커**가 Redis Streams(`analysis.jobs`)로 작업을 받아 결과 이벤트(`analysis.events`)만 돌려준다. 워커는 DB에 쓰지 않는다.
- 워커는 HTTP 서버가 필요 없다. 헬스체크·메트릭이 필요하면 그때 얇게 붙인다.

## 결과

- 좋아지는 점
  - 상태 머신, 멱등 처리, 개인정보 삭제처럼 복잡한 도메인 규칙을 Java 생태계(JPA, ArchUnit)로 다룬다.
  - API는 CPU 서버, 워커는 GPU(로컬·Colab·대여)에서 따로 배포·확장한다.
  - FastAPI 하나로 해도 GPU 작업용 워커 프로세스는 따로 필요했으므로 배포 단위가 늘지 않는다.
- 감수할 점
  - 언어가 둘이라 메시지 형식이 어긋날 수 있다 → JSON Schema 파일 하나를 양쪽이 검증에 쓴다([ADR-0004](0004-분석-단계와-메시지-계약.md)).
  - 즉시 응답이 필요한 FR-07(누락 홀드 탭)은 큐 대기 시간이 문제다 → 별도 우선순위 스트림([ADR-0004](0004-분석-단계와-메시지-계약.md)).
