# ADR-0003 인증: 카카오 소셜 로그인 + JWT

- 상태: 제안
- 날짜: 2026-10-13

## 배경

- 이용자는 클라이밍 크루원이고, 가입 장벽이 낮아야 한다.
- 비밀번호를 직접 저장하면 해시, 재설정 메일, 이메일 인증까지 만들어야 하고 개인정보 부담이 커진다.
- 카카오 로그인은 이메일 제공이 **선택 동의**이고, 필수로 받으려면 비즈 앱 심사가 필요하다. ERD는 `climber.email`만 있어 이메일을 신원으로 쓸 수 없다.
- 클라이언트는 웹 SPA다(MVP).

## 결정

- **로그인:** 카카오 OAuth2 Authorization Code 방식. 프런트가 받은 인가 코드를 `POST /v1/auth/kakao`로 보내면 서버가 카카오와 토큰을 교환하고 사용자 정보를 조회한다. 구글은 필요해지면 같은 구조로 추가한다.
- **신원:** `(provider, providerUserId)`가 회원의 신원이다. 이메일은 받으면 저장하고, 없어도 가입된다.
- **토큰:**
  - access token: JWT, 유효 30분, `Authorization: Bearer` 헤더로 보낸다. 프런트는 메모리에만 둔다.
  - refresh token: 무작위 문자열, 유효 14일, **HttpOnly·Secure·SameSite=Strict 쿠키**로 보낸다. 서버는 해시를 Redis에 저장하고, 재발급할 때마다 새 토큰으로 바꾼다(rotation). 이미 쓴 refresh token이 다시 오면 그 회원의 refresh token을 모두 폐기한다.
  - 로그아웃은 refresh token을 Redis에서 지운다.
- **역할:** JWT에 `role`(CLIMBER / COACH)을 넣는다. 코치 지정은 관리자가 한다.
- **회원 탈퇴:** 카카오 연결 끊기(unlink)를 호출하고 `ClimberWithdrawn` 이벤트를 발행한다.

## 결과

- 좋아지는 점
  - 비밀번호 관련 기능과 저장 부담이 없다.
  - refresh token rotation과 HttpOnly 쿠키로 토큰 탈취 피해를 줄인다.
- 감수할 점
  - 카카오 장애 시 로그인할 수 없다.
  - 이메일이 없는 회원에게는 메일로 연락할 수 없다.
  - SPA와 API 도메인이 다르면 쿠키 설정(SameSite, CORS credentials)을 맞춰야 한다 → M2에서 배포 도메인을 정하고 확인한다.
