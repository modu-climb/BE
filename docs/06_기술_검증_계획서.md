# 기술 검증 계획서

> 🧪 4주차 말까지 같은 영상 20\~30편에 세 가지 분석 구성(A/B/C안)을 적용해 비교하고, MVP를 어떤 구성으로 만들지 데이터로 결정한다. 지원서에서 약속한 "자세만 쓴 분석 vs 깊이 결합 분석" 비교를 확장한 실험이다.

관련 문서: [기능 명세서](02_기능_명세서.md) · [시스템 아키텍처](03_시스템_아키텍처.md) · [WBS](05_WBS.md)

## 1. 비교 대상

| 안 | 구성 | 가설 | 실행 환경 |
| --- | --- | --- | --- |
| **A안** (기준선) | 2D 포즈만 사용. 관절 각도·접촉·실패 지점을 화면 좌표로 계산 | 가장 싸고 단순하다. 정면 촬영에서는 이것만으로 충분할 수 있다 | 로컬 3070 |
| **B안** (기존 설계) | 2D 포즈 + 키프레임별 Marigold V2 깊이, 벽 픽셀 기반 프레임 간 정렬 | 관절 위치의 깊이로 골반-벽 거리를 얻는다. 가려진 관절과 표면 깊이 문제가 있다 | Colab L4 |
| **C안** (추천안) | SAM 3D Body 3D 인체 복원 + 벽 기준 이미지 1장에 Marigold V2·MoGe-2 + 접촉 지점 기반 사람-벽 정렬 | 3D 관절 각도와 골반-벽 거리가 가장 정확하고, 깊이 추정 비용이 벽 장면당 1회로 줄어든다 | 로컬 3070(인체 복원, MoGe-2) + Colab(Marigold V2) |

세 안은 P0\~P3(입력 검증, 벽 기준 이미지, 홀드 세그멘테이션, 문제 소속)과 P7(피드백 생성 규칙)을 공유한다. P4\~P6만 다르게 구현해 차이가 분석 구성에서만 나오게 한다.

## 2. 평가 데이터

- **영상 20\~30편:** 1인 볼더링, 고정 촬영, 30\~60초.
- **조건을 섞는다:** 벽 각도(수직·약한 오버행·강한 오버행), 촬영 각도(정면·사선 30\~45°), 난이도(초급·중급), 성공·실패 시도.
- **기준값 영상 5편:** 정면 카메라와 함께 **측면에 스마트폰을 한 대 더 두고 동시 촬영**한다. 측면 영상에서 골반-벽 거리와 무릎·골반 각도를 수동으로 재서 정답으로 쓴다.
- **수동 라벨:** 모든 영상에 손발 접촉 시점(어느 손발이 어느 홀드를 몇 프레임부터)과 실패 지점을 라벨링한다.
- 촬영·학습 활용 동의를 받은 영상만 쓴다.

## 3. 평가 지표

### 자동 지표

| 지표 | 측정 방법 | 대상 안 |
| --- | --- | --- |
| 골반-벽 거리 오차 | 측면 기준값 대비 평균 절대 오차(cm) | B, C (A는 측정 불가) |
| 관절 각도 오차 | 측면 기준값 대비 무릎·골반 각도 평균 절대 오차(°) | A, B, C |
| 접촉 이벤트 정확도 | 수동 라벨 대비 정밀도·재현율(±5프레임 허용) | A, B, C |
| 실패 지점 정확도 | 수동 라벨 대비 시점 오차(초) | A, B, C |
| 분석 가능 비율 | 오류·저신뢰로 지표를 못 낸 영상을 뺀 비율 | A, B, C |
| 인체 복원 실패율 | 관절 신뢰도가 임계값 미만인 프레임 비율, 자세 유형별 집계 | C |
| 정렬 잔차 | 접촉 지점에서 손발 깊이와 벽 깊이의 차이 | B(프레임 간), C(사람-벽) |
| 영상당 GPU 시간 | 단계별 실측(초), 첫 시도와 재시도 구분 | A, B, C |

### 코치 블라인드 평가

- 각 영상의 리포트 세 개를 안 이름을 가린 채 무작위 순서로 보여준다.
- 코치 2명 이상이 리포트마다 **정확성, 유용성(다음 시도에 바로 쓸 수 있는가), 구체성**을 1\~5점으로 매기고, 세 리포트의 순위를 정한다.
- 리포트 문장은 같은 P7 규칙과 같은 LLM 프롬프트로 만든다. 문장 품질이 아니라 분석 구성의 차이를 보기 위해서다.

## 4. 판정 기준

아래 수치는 제안값이며, 1주차에 팀과 코치 의견을 반영해 확정한다.

| 결과 | 결정 |
| --- | --- |
| C안 코치 평균이 A안보다 0.5점 이상 높고, 인체 복원 실패율 30% 미만 | **C안 채택.** 현재 기능 명세서대로 진행 |
| B안과 C안 차이가 0.3점 미만 | GPU 비용과 구현 복잡도가 낮은 쪽 채택 |
| 세 안 모두 차이가 0.3점 미만 | **A안으로 MVP.** 깊이는 시각화 보조로 두고 3D 분석은 확장 기능으로 미룬다 |
| C안 인체 복원 실패율 30% 이상 | C안 보류. 실패 자세 유형을 분석해 파인튜닝이나 대안 모델을 검토하고, 그동안은 A안 또는 B안으로 진행 |
| 모든 안의 분석 가능 비율이 70% 미만 | 분석 구성보다 촬영 조건이 문제다. 촬영 가이드를 먼저 고친다 |

## 6. 실행 환경과 기록 방식

- **로컬 RTX 3070(8GB):** A안 전체, 2D 포즈, 홀드 세그멘테이션, MoGe-2 작은 모델. SAM 3D Body가 8GB에서 도는지 1주차에 확인하고, 안 되면 Colab으로 옮긴다.
- **Colab Pro:** Marigold V2(L4 24GB로 1024px, A100으로 2048px). 무료 T4(16GB)는 메모리가 부족하다.
- **코드:** 파이프라인은 git 저장소의 Python 패키지로 만들고 노트북은 호출만 한다. 모델 선택은 설정 파일로 바꾼다. 나중에 같은 코드로 워커를 만들기 위해서다.
- **기록:** 실행마다 pipelineVersion, 모델 버전, 단계별 소요 시간, GPU 종류를 CSV로 남긴다. 이 기록이 인프라 규모와 GPU 비용 산정의 근거가 된다.
