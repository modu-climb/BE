# 개발 컨벤션

작업은 **이슈 생성 → 브랜치 생성 → 커밋 → PR** 순서로 진행합니다.

## 1. 타입

이슈·PR 제목의 말머리와 커밋·브랜치의 접두사는 같은 타입을 씁니다.

| 이슈·PR 말머리 | 커밋·브랜치 접두사 | 용도 |
| --- | --- | --- |
| `[FEAT]` | `feat` | 새 기능 |
| `[FIX]` | `fix` | 버그 수정 |
| `[REFACTOR]` | `refactor` | 동작 변경 없는 구조 개선 |
| `[DOCS]` | `docs` | 문서 |
| `[TEST]` | `test` | 테스트 추가·수정 |
| `[CHORE]` | `chore` | 빌드, 설정, 의존성, CI 등 |

## 2. 이슈

브랜치를 만들기 전에 이슈를 먼저 만듭니다.

- **제목:** `[FEAT] 홀드 선택 기능 구현`
- **본문:** 아래 형식으로 간단하게 요약합니다.

```markdown
# 개요
무엇을 왜 하는지

# 구현 범위
- 이번 이슈에서 다루는 것

# 체크리스트
- [ ] 할 일
```

## 3. 브랜치

`{타입}/#{이슈 번호}/{이슈 제목}` 형식이며, 이슈 제목에서 말머리를 빼고 공백을 `-`로 바꿉니다.

```
feat/#1/홀드-선택-기능-구현
fix/#12/업로드-URL-만료-오류-수정
```

셸에서 `#`이 주석으로 해석되지 않도록 브랜치명을 따옴표로 감쌉니다.

```bash
git switch -c "feat/#1/홀드-선택-기능-구현"
```

## 4. 커밋

- 소문자 타입 뒤에 `: `를 붙이고, **제목 한 줄만** 간단하게 씁니다.
- 본문은 쓰지 않습니다.

```
feat: 홀드 선택 API 추가
fix: 업로드 완료 중복 요청 처리
docs: 컨벤션 문서 추가
```

## 5. PR

- **제목:** 이슈와 같은 말머리를 붙입니다. 예: `[FEAT] 홀드 선택 기능 구현`
- **본문:** 아래 형식으로 작성하고, 관련 이슈를 닫도록 연결합니다.

```markdown
# 개요
무엇을 왜 했는지 (closes #1)

# 구현 내용
- 변경한 내용

# 체크리스트
- [ ] 테스트 통과
```

## 6. 금지 사항

- 이슈, 커밋, PR 어디에도 `Co-Authored-By`를 넣지 않습니다.
