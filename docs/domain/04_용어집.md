## 시도·분석

| 한글 | 영문 | 코드명 | 뜻 |
| --- | --- | --- | --- |
| 시도 | Attempt | `Attempt` | 등반 한 번. 영상 하나에 시도 하나 |
| 시도 번호 | Attempt number | `attemptNo` | 같은 문제 안에서 몇 번째 시도인지(1부터) |
| 재시도 (등반) | Retry attempt | — | 같은 문제를 다시 오른 새 시도. 확정된 홀드를 재사용한다 |
| 분석 작업 | Analysis job | `AnalysisJob` | 시도 하나를 분석하는 상태 머신 |
| 작업 상태 | Job state | `JobState` | `REQUESTED` \~ `COMPLETED` 등 작업의 현재 상태 |
| 실행 단계 | Phase | `JobPhase.PREPROCESS/INFER_PROBLEM/ANALYZE` | 워커에 한 번에 맡기는 처리 묶음 |
| 파이프라인 단계 | Pipeline step | `P0`\~`P7` | 워커 내부의 세부 처리 단계. 백엔드 코드에는 쓰지 않는다 |
| 실행 회차 | Run number | `runNo` | 같은 실행 단계를 몇 번째 실행했는지. 이벤트 중복 제거에 쓴다 |
| 재시도 (작업) | Job retry | `retryCount` | 실패한 실행 단계를 다시 발행한 횟수. 작업당 최대 2회 |
| 반려 | Rejection | `JobState.REJECTED` | 입력 영상이 부적합해 분석하지 않음. 재시도하지 않는다 |
| 만료 | Expiration | `JobState.EXPIRED` | 사용자 입력을 7일 동안 기다렸지만 응답이 없음 |
| 사용자 입력 대기 | Awaiting user input | `AWAITING_HOLD_SELECTION`, `AWAITING_CONFIRMATION` | 작업이 멈춰 사용자를 기다리는 상태 |
| 산출물 | Artifact | `AnalysisArtifact` | 단계가 만든 파일(키프레임, 깊이, 포즈 등)의 스토리지 키 |
| 파이프라인 버전 | Pipeline version | `pipelineVersion` | 결과를 만든 워커 코드 버전 |
| 모델 식별자 | Model versions | `modelVersions` | 결과를 만든 모델 이름·버전 목록. 도메인 규칙에 쓰지 않는다 |
| 워커 | Worker | — | 분석을 실행하는 Python GPU 프로세스 |

> ⚠️ **"재시도"는 두 가지 뜻이 있다.** 등반 재시도는 같은 문제의 새 **시도(Attempt)**이고, 작업 재시도는 실패한 **실행 단계의 재발행(runNo 증가)**이다. 코드와 문서에서는 `Attempt`와 `runNo`·`retryCount`로 구분하고, 말로 할 때도 "등반 재시도", "작업 재시도"로 구분한다.

## 쓰지 않는 말

| 쓰지 않는 말 | 대신 쓰는 말 | 이유 |
| --- | --- | --- |
| 루트(route) | 문제(problem) | 볼더링에서는 문제가 일반적이고, ERD도 problem을 쓴다 |
| 유저(user), 멤버 | 클라이머(climber) | 도메인 언어와 테이블명을 맞춘다. 패키지명만 `member`로 둔다 |
| 작업의 `attemptNo` | `runNo` | 등반 시도 번호와 헷갈린다 |
| `PHASE_1`, `PHASE_2` | `PREPROCESS`, `INFER_PROBLEM`, `ANALYZE` | 번호만으로는 무엇을 하는 단계인지 알 수 없다 |
